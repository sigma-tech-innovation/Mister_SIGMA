- **Catégorie :** Reprise de session
- **Propriétaire cible :** Dossier maître avec renvois vers les propriétaires
- **Source :** `Mister_SIGMA_Dossier_Maitre_Continuite_Partie_12.docx`
- **Paragraphes :** 13
- **Titres détectés :** 11

  - Mister_SIGMA — Dossier Maître de Continuité
  - Partie 12 — Règles de reprise d'une session de développement
  - 1. Vérifier la branche Git active et l'état du working tree.
  - 2. Contrôler les derniers commits pour connaître le contexte immédiat.
  - 3. Localiser les classes et méthodes concernées avec grep avant toute modification.
  - 4. Afficher uniquement la zone ciblée avec sed afin d'identifier un point d'insertion unique.
  - 5. Modifier le code par patch ciblé, sans remplacement global ambigu.
  - 6. Compiler les fichiers modifiés, exécuter les tests ciblés puis la suite complète.
  - 7. Exécuter Doctor, Health et Sync Validate avant toute proposition de commit.
  - 8. Ne créer un commit qu'après validation complète et working tree cohérent.
  - Principe directeur
